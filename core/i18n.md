# 国际化

## 一句话定义

`tr()` 和 `trn()` 描述可翻译文案，组件绑定后随 `setLocale()` 更新；语言包可以嵌入程序，也可以从文件加载。

运行时接口位于 `<hiyui/core/i18n.h>`，文件加载接口位于 `<hiyui/platform/i18n_files.h>`，两者均由 `<hiyui/hiyui.h>` 引入。所有国际化运行时操作在 UI 线程调用。

## 对照表

| 用途 | C++ | C |
| --- | --- | --- |
| 文案描述 | `LocalizedText`、`TextArg` | `hiyui_localized_text_t`、`hiyui_text_arg_t` |
| 普通消息 | `tr()` | `hiyui_tr()` |
| 整数复数消息 | `trn()` | `hiyui_trn()` |
| 绑定按钮文字 | `Button::text(LocalizedText)` | `hiyui_button_bind_text()` |
| 切换语言 | `setLocale()` | `hiyui_set_locale()` |
| 当前语言、源语言 | `currentLocale()`、`sourceLocale()` | `hiyui_current_locale()`、`hiyui_source_locale()` |
| 可用语言 | `availableLocales()` | `hiyui_available_locales()` |
| 注册内存语言包 | `registerLanguagePack()` | `hiyui_language_pack_register()` |
| 加载文件、目录 | `loadLanguagePackFile()`、`loadLanguageDirectory()` | `hiyui_language_pack_load_file()`、`hiyui_language_directory_load()` |
| 导出源文案 | `exportMessages()` | `hiyui_i18n_export_messages()` |

Props 中的文字字段仍接收 `const char *`。使用链式方法绑定翻译；普通字符串 setter 取消对应属性的翻译绑定。

## 代码示例

以下 `main.cpp` 使用后文 CMake 配置生成的 `app_i18n.h`，在创建界面前注册语言包。

```cpp
#include <hiyui/hiyui.h>
#include "app_i18n.h"

class App final : public hiyui::Application {
  void setup() override {
    auto &window = createWindow({.title = "I18n"});
    window.root(hiyui::Button{}.text(hiyui::tr("app.save", "保存")));
  }
};

int main() {
  if (const int status = app_i18n_register_languages())
    return status;
  if (hiyui::setLocale("en-US") != hiyui::I18nStatus::Success)
    return 1;
  return App{}.run();
}
```

`LocalizedText` 保存 ID、源文案和参数。`TextArg` 的值接受 `std::string`、`int64_t`、`uint64_t` 和 `double`。组件绑定时复制描述，组件销毁时解除绑定。语言切换保留输入内容和集合选中状态。更新参数时重新调用对应绑定方法。

以下片段为已创建的标签绑定具名参数与计数；`nameLabel` 和 `countLabel` 均为 `Label`。

```cpp
using namespace hiyui;

nameLabel.text(tr("app.hello", "你好，{name}",
                  {{"name", std::string("小明")}}));
countLabel.text(trn("app.files", "共 {count} 个文件", "共 {count} 个文件", 3));
std::string saved = translate(tr("app.save", "保存"));
```

`translate()` 返回独立的 UTF-8 字符串，不创建组件绑定。参数名称由 ASCII 字母、数字或下划线组成，不能以数字开头。文案中的花括号按 fmt 规则转义，两个连续 `{` 表示字面花括号。不支持位置参数及格式规格，例如 `{0}` 或 `{value:.2f}`。参数不匹配时返回未格式化的源文案。

`trn()` 自动提供 `count` 参数，其他参数不能重复该名称。当前复数规则覆盖中、英、日、韩：英语在计数为 `1` 或 `-1` 时使用 `one`，其余使用 `other`；中、日、韩使用 `other`。

## 制作语言包

`scripts/i18n.py` 使用 Python 3 标准库。工具在开发和构建时运行，应用运行时不依赖 Python。以下命令在应用项目目录执行，`HIYUI/scripts/i18n.py` 替换为实际工具路径；Windows 也可使用 `py -3` 调用。

从应用的 C、C++ 和 XML 源文件导出消息，并创建或更新英语翻译目录。

```bash
python HIYUI/scripts/i18n.py extract --sources main.cpp ui --source-locale zh-CN --out messages.json
python HIYUI/scripts/i18n.py sync --catalog messages.json --locale en-US --out locales/en-US.json
```

消息 ID 必须非空且稳定。同一 ID 的源文案必须一致；不同语境使用不同 ID。提取器识别 `tr`、`trn`、`hiyui_tr`、`hiyui_trn` 和 XML 的 `{i18n:id|source}`，ID 与源文案必须直接写成字符串字面量。普通 Props 字符串不会自动收集。程序生成的消息目录通过 `extract --catalog 文件.json` 合并，该参数可重复。

在 `sync` 生成的记录中填写 `translation`，将 `status` 改为 `translated`，保留 `source`、`sourcePlural` 和 `sourceHash`。普通消息的 `translation` 是字符串，以下值可用于英语复数消息的 `translation` 字段。

```json
{
  "one": "{count} file",
  "other": "{count} files"
}
```

再次执行 `sync` 会保留已有译文，将源文案变化的条目标为 `needs-review`，将已移除条目移入 `obsolete`。完成复核后再设为 `translated`。译文必须保留与源文案一致的参数名称。

完成翻译后校验并生成可分发文件。

```bash
python HIYUI/scripts/i18n.py check messages.json locales/en-US.json --strict
python HIYUI/scripts/i18n.py pack --input locales/en-US.json --out languages/en-US.hylang --strict
```

`--strict` 拒绝未完成或待复核条目。不指定时，打包跳过非 `translated` 条目，运行时按缺失翻译处理。每次源文案变化后先重新提取并执行 `sync`；`check` 校验传入目录各自的内容，不比较两个文件的新旧关系。

运行时读取 `.hylang` 文件。JSON 用于编辑、脚本处理和版本管理。

## 嵌入与单文件发布

在链接 HIY-UI 后调用 `target_link_i18n()`。下面的 `app` 目标使用源文案和英语翻译生成嵌入资源。

```cmake
add_executable(app main.cpp)
target_link_libraries(app PRIVATE hiyui-static)
target_link_i18n(app
    SOURCE_LOCALE zh-CN
    SYMBOL_PREFIX app_i18n
    SOURCES main.cpp ui
    TRANSLATIONS locales/en-US.json
)
```

首次尚未创建翻译文件时省略 `TRANSLATIONS`。配置阶段生成 `<目标构建目录>/i18n/app/messages.json`，可直接用于 `sync`。安装版 SDK 链接目标为 `hiyui::hiyui`，使用相同辅助函数。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `SOURCE_LOCALE` | `zh-CN` | 应用源语言 |
| `SYMBOL_PREFIX` | 目标名加 `_i18n`，转换为 C 标识符 | 生成头文件及注册函数的名称前缀 |
| `SOURCES` | 空 | 提取文案的文件或目录；相对当前 CMake 源目录 |
| `CATALOGS` | 空 | 合并到源目录的 JSON 消息目录 |
| `TRANSLATIONS` | 空 | 要嵌入的翻译 JSON 文件 |
| `PACKS` | 空 | 已生成的 `.hylang` 文件 |
| `C_BINDING` | 关闭；直接链接 C 绑定目标时自动开启 | 通过 C API 注册到 C 绑定使用的国际化状态 |

辅助函数嵌入源文案目录、库内英语/日语/韩语译文和应用指定的译文，复用 `target_link_embed()`。语言数据随可执行文件发布，无需附带 JSON、`.hylang` 或 Python。其他应用资源和依赖仍按各自的发布方式处理。

生成的头文件为 `<SYMBOL_PREFIX>.h`，注册函数为 `int <SYMBOL_PREFIX>_register_languages(void)`。应用启动时显式调用一次，再选择语言、创建界面。返回 `0` 表示成功，其他值对应 `I18nStatus`。

只传 `PACKS`、不传 `SOURCES`、`CATALOGS` 和 `TRANSLATIONS` 时，此辅助函数不执行 Python，仅嵌入指定包，也不自动添加库内目录。需要运行时导出时，把通过 `pack --source` 制作的源文案包一并传入。

## 外置语言包

已嵌入的译文可由外置包覆盖。下面的函数加载目录后切换语言，并向调用方返回失败状态。

```cpp
hiyui::I18nStatus useExternalEnglish() {
  const auto status = hiyui::loadLanguageDirectory("languages");
  if (status != hiyui::I18nStatus::Success)
    return status;
  return hiyui::setLocale("en-US");
}
```

目录加载只读取该目录直接包含的 `.hylang` 普通文件，按路径排序。任一文件无效时保留之前的整组语言包；成功时替换该目录上次加载的包。`loadLanguagePackFile()` 只加载一个文件，同路径成功重载时替换旧包。路径使用 UTF-8；文件变化后由应用再次调用加载函数，不自动监视文件。

文件接口在 SDL 和 FBDEV 后端可用，其他后端返回 `Unavailable`。无文件系统的应用可从自身存储中取得字节，通过 `registerLanguagePack(data, size)` 注册。

内存注册默认使用 `LanguagePackStorage::Copy` 和 `LanguagePackLayer::External`，调用时复制数据。`Static` 要求字节在程序生命周期内始终有效且不可修改。成功结果的 `id` 可传给 `removeLanguagePack()`；失败时 `id` 为 `0`，原有包及当前语言保持不变。

## 语言选择与回退

初始源语言和当前语言均为 `zh-CN`。语言标识使用连字符，例如 `zh-CN`、`en-US`、`ja-JP`、`ko-KR`；输入的大小写会规范化。不自动将 `en-US` 推导为 `en`。

| 方法 | 返回 | 说明 |
| --- | --- | --- |
| `setLocale(const char *)` | `I18nStatus` | 切换已注册语言或源语言，并更新绑定；语言不可用时保留当前语言 |
| `setSourceLocale(const char *)` | `I18nStatus` | 设置源语言；当前语言等于原源语言时同步切换 |
| `setFallbackLocales({"en-US", "ja-JP"})` | `I18nStatus` | 设置有序回退列表，无对应包的项跳过；空列表清除配置 |
| `currentLocale()`、`sourceLocale()` | `std::string` | 返回当前语言、源语言的独立字符串 |
| `availableLocales()` | `std::vector<std::string>` | 返回已注册语言和源语言，不含重复项 |
| `removeLanguagePack(uint64_t)` | `I18nStatus` | 移除包并刷新绑定；不存在的 ID 返回 `InvalidArgument` |
| `clearLanguagePacks()` | `void` | 清空包并恢复源语言，绑定显示源文案 |
| `exportMessages()` | `std::string` | 导出已注册内置源文案目录，返回 JSON |

每条消息按当前语言、显式回退列表、源语言的顺序查找；各语言中外置包覆盖内置包，同层使用最后注册且源文案匹配的消息。全部缺失时显示描述中的源文案。源文案或复数源文案不匹配的旧翻译不参与查找。

移除当前语言的最后一个包后，当前语言名称保留，消息按上述回退顺序显示。需要返回源语言时显式调用 `setLocale(sourceLocale().c_str())` 或清空全部语言包。

| 值 | 说明 |
| --- | --- |
| `Success` | 操作成功 |
| `InvalidArgument` | 参数无效，例如空语言标识或不存在的包 ID |
| `InvalidPack` | 语言包内容未通过校验 |
| `UnsupportedVersion` | 语言包版本不受支持 |
| `LocaleUnavailable` | 请求的语言未注册且不是源语言 |
| `IoError` | 文件或目录访问失败 |
| `OutOfMemory` | 语言包注册或加载时分配内存失败 |
| `Unavailable` | 当前后端不提供该操作 |

## 运行时导出

`exportMessages()` 返回已注册为 `Builtin` 的源文案目录，包含已提取但尚未打开的页面。应用把结果写为 JSON 后，可直接交给 `sync`。它不扫描当前组件树，也不收集未标记的普通字符串。

导出内容取决于构建时的 `SOURCES` 和 `CATALOGS`。动态生成的文案需要事先加入消息目录并嵌入源包。画廊提供 [`--export-i18n`](/build/cpp-gallery#国际化) 命令行入口。

## C 接入

头文件为 `<hiyui/c/i18n.h>`，也由 `<hiyui/c/hiyui.h>` 引入。C 项目使用同一个 `target_link_i18n()`，链接 `hiyui-c` 或 SDK 的 `hiyui::hiyui-c`；间接链接时显式加上 `C_BINDING`。在创建界面前调用生成的注册函数，再调用 `hiyui_set_locale()`。

以下片段在已创建的 `label` 句柄上绑定具名参数。

```c
hiyui_text_arg_t arguments[] = {
    {.name = "name", .kind = HIYUI_TEXT_ARG_STRING, .text = "小明"}
};
hiyui_localized_text_t message = hiyui_tr("app.hello", "你好，{name}");
message.arguments = arguments;
message.argument_count = 1;
hiyui_i18n_status_t status = hiyui_label_bind_text(label, message);
```

`hiyui_tr()` 和 `hiyui_trn()` 返回引用调用方数据的描述；绑定或查询在调用时复制输入，此后可释放参数和文案。句柄必须仍存活且属于对应组件类型；空句柄返回 `HIYUI_I18N_INVALID_ARGUMENT`。普通文字 setter 取消相应绑定。

`hiyui_translate()`、`hiyui_current_locale()`、`hiyui_source_locale()`、`hiyui_available_locales()` 和 `hiyui_i18n_export_messages()` 使用调用方缓冲区。传入 `NULL, 0` 可查询包含结尾 NUL 的所需字节数；返回 `0` 表示失败。容量不足且大于 `0` 时写入空串，不返回截断文字。语言列表使用换行分隔。

`hiyui_language_pack_register()` 的 `static_data` 和 `builtin` 分别控制数据生命周期与包层级；均为假时复制数据并注册为外置包。静态 C 绑定构建见 [C 画廊](/build/c-gallery#静态链接)。

## 字体与范围

语言包不包含字体。应用需要提供覆盖目标语言的字体；嵌入式平台仍可使用 LVGL 点阵字体。

以下命令导出消息源文案和可打包译文中的静态字符集合，供字体裁剪使用。

```bash
python HIYUI/scripts/i18n.py charset messages.json locales/en-US.json --out characters.txt
```

该集合不包含运行时参数可能带来的字符，姓名、用户输入等字符范围由应用另行提供。当前国际化接口不提供 RTL 布局切换，也不提供完整的地区日期、时间和数字格式化。
