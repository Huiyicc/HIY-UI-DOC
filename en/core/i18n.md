# Internationalization

## Definition

`tr()` and `trn()` describe translatable text; widget bindings update on `setLocale()`. Language packs can be embedded in the program or loaded from files.

The runtime interface is in `<hiyui/core/i18n.h>` and the file loading interface in `<hiyui/platform/i18n_files.h>`; both are included by `<hiyui/hiyui.h>`. All i18n runtime operations are called on the UI thread.

## Comparison table

| Purpose | C++ | C |
| --- | --- | --- |
| Text description | `LocalizedText`, `TextArg` | `hiyui_localized_text_t`, `hiyui_text_arg_t` |
| Plain message | `tr()` | `hiyui_tr()` |
| Integer plural message | `trn()` | `hiyui_trn()` |
| Bind button text | `Button::text(LocalizedText)` | `hiyui_button_bind_text()` |
| Switch language | `setLocale()` | `hiyui_set_locale()` |
| Current and source locale | `currentLocale()`, `sourceLocale()` | `hiyui_current_locale()`, `hiyui_source_locale()` |
| Available locales | `availableLocales()` | `hiyui_available_locales()` |
| Register in-memory language pack | `registerLanguagePack()` | `hiyui_language_pack_register()` |
| Load file, directory | `loadLanguagePackFile()`, `loadLanguageDirectory()` | `hiyui_language_pack_load_file()`, `hiyui_language_directory_load()` |
| Export source messages | `exportMessages()` | `hiyui_i18n_export_messages()` |

Text fields in Props still accept `const char *`. Bind translations with chained methods; a plain string setter removes the translation binding of the corresponding property.

## Code example

The following `main.cpp` uses the `app_i18n.h` generated by the CMake configuration described later and registers language packs before creating the interface.

```cpp
#include <hiyui/hiyui.h>
#include "app_i18n.h"

class App final : public hiyui::Application {
  void setup() override {
    auto &window = createWindow({.title = "I18n"});
    window.root(hiyui::Button{}.text(hiyui::tr("app.save", "保存")));
  }
};

int main() {
  if (const int status = app_i18n_register_languages())
    return status;
  if (hiyui::setLocale("en-US") != hiyui::I18nStatus::Success)
    return 1;
  return App{}.run();
}
```

`LocalizedText` stores an ID, source text, and arguments. `TextArg` values accept `std::string`, `int64_t`, `uint64_t`, and `double`. Binding copies the description, and the binding is removed when the widget is destroyed. Language switching preserves input content and collection selection state. To update arguments, call the corresponding binding method again.

The following fragment binds a named argument and a count to created labels; `nameLabel` and `countLabel` are both `Label`.

```cpp
using namespace hiyui;

nameLabel.text(tr("app.hello", "你好，{name}",
                  {{"name", std::string("小明")}}));
countLabel.text(trn("app.files", "共 {count} 个文件", "共 {count} 个文件", 3));
std::string saved = translate(tr("app.save", "保存"));
```

`translate()` returns an independent UTF-8 string and creates no widget binding. Parameter names consist of ASCII letters, digits, or underscores and cannot start with a digit. Braces in text are escaped following fmt rules; two consecutive `{` denote a literal brace. Positional arguments and format specifications such as `{0}` or `{value:.2f}` are not supported. When arguments do not match, the unformatted source text is returned.

`trn()` provides the `count` argument automatically, and other arguments must not reuse that name. The current plural rules cover Chinese, English, Japanese, and Korean: English uses `one` when the count is `1` or `-1` and `other` otherwise; Chinese, Japanese, and Korean use `other`.

## Authoring language packs

`scripts/i18n.py` uses the Python 3 standard library. The tool runs during development and building; the application does not depend on Python at runtime. Run the following commands in the application project directory, replacing `HIYUI/scripts/i18n.py` with the actual tool path; on Windows, `py -3` can be used to invoke it.

Extracts messages from the application's C, C++, and XML source files and creates or updates the English translation catalog.

```bash
python HIYUI/scripts/i18n.py extract --sources main.cpp ui --source-locale zh-CN --out messages.json
python HIYUI/scripts/i18n.py sync --catalog messages.json --locale en-US --out locales/en-US.json
```

Message IDs must be non-empty and stable. Source text for the same ID must be identical; use different IDs for different contexts. The extractor recognizes `tr`, `trn`, `hiyui_tr`, `hiyui_trn`, and the XML `{i18n:id|source}` form; the ID and source text must be written directly as string literals. Plain Props strings are not collected automatically. Programmatically generated message catalogs are merged through `extract --catalog <file>.json`, and this argument can be repeated.

Fill in `translation` in the records produced by `sync`, change `status` to `translated`, and keep `source`, `sourcePlural`, and `sourceHash`. The `translation` of a plain message is a string; the following values can be used in the `translation` field of an English plural message.

```json
{
  "one": "{count} file",
  "other": "{count} files"
}
```

Running `sync` again keeps existing translations, marks entries whose source text changed as `needs-review`, and moves removed entries into `obsolete`. Set them back to `translated` after review. Translations must keep parameter names matching the source text.

After translation is complete, validate and generate the distributable files.

```bash
python HIYUI/scripts/i18n.py check messages.json locales/en-US.json --strict
python HIYUI/scripts/i18n.py pack --input locales/en-US.json --out languages/en-US.hylang --strict
```

`--strict` rejects unfinished or review-pending entries. Without it, packing skips entries that are not `translated`, and the runtime treats them as missing translations. After each source text change, extract again and run `sync` first; `check` validates the content of each catalog passed to it and does not compare the two files for freshness.

The runtime reads `.hylang` files. JSON is used for editing, scripted processing, and version management.

## Embedding and single-file release

Call `target_link_i18n()` after linking HIY-UI. The following `app` target generates embedded resources from the source text and the English translation.

```cmake
add_executable(app main.cpp)
target_link_libraries(app PRIVATE hiyui-static)
target_link_i18n(app
    SOURCE_LOCALE zh-CN
    SYMBOL_PREFIX app_i18n
    SOURCES main.cpp ui
    TRANSLATIONS locales/en-US.json
)
```

Omit `TRANSLATIONS` when no translation file has been created yet. The configure stage generates `<target build directory>/i18n/app/messages.json`, which can be used directly for `sync`. The installed SDK links `hiyui::hiyui` and uses the same helper function.

| Parameter | Default | Description |
| --- | --- | --- |
| `SOURCE_LOCALE` | `zh-CN` | Application source language |
| `SYMBOL_PREFIX` | Target name plus `_i18n`, converted to a C identifier | Name prefix of the generated header and registration function |
| `SOURCES` | empty | Files or directories to extract text from; relative to the current CMake source directory |
| `CATALOGS` | empty | JSON message catalogs merged into the source catalog |
| `TRANSLATIONS` | empty | Translation JSON files to embed |
| `PACKS` | empty | Already generated `.hylang` files |
| `C_BINDING` | off; enabled automatically when directly linking a C binding target | Registers the i18n state used by the C binding through the C API |

The helper embeds the source text catalog, the English/Japanese/Korean translations shipped with the library, and the translations specified by the application, reusing `target_link_embed()`. Language data ships with the executable; no JSON, `.hylang`, or Python needs to accompany it. Other application resources and dependencies are still released through their own channels.

The generated header is `<SYMBOL_PREFIX>.h` and the registration function is `int <SYMBOL_PREFIX>_register_languages(void)`. Call it explicitly once at application startup, then select the language and create the interface. A `0` return means success; other values correspond to `I18nStatus`.

When only `PACKS` is passed and `SOURCES`, `CATALOGS`, and `TRANSLATIONS` are omitted, the helper executes no Python, embeds only the given packs, and does not add the library catalogs automatically. When runtime export is needed, also pass a source text pack produced with `pack --source`.

## External language packs

Embedded translations can be overridden by external packs. The following function loads a directory, switches the language, and returns the failure status to the caller.

```cpp
hiyui::I18nStatus useExternalEnglish() {
  const auto status = hiyui::loadLanguageDirectory("languages");
  if (status != hiyui::I18nStatus::Success)
    return status;
  return hiyui::setLocale("en-US");
}
```

Directory loading reads only regular `.hylang` files directly contained in the directory, ordered by path. If any file is invalid, the previous set of language packs is kept; on success it replaces the packs loaded from that directory last time. `loadLanguagePackFile()` loads a single file and replaces the old pack when the same path is reloaded successfully. Paths use UTF-8; after files change, the application calls the loading functions again; files are not watched automatically.

The file interface is available on the SDL and FBDEV backends; other backends return `Unavailable`. Applications without a file system can obtain bytes from their own storage and register them through `registerLanguagePack(data, size)`.

In-memory registration defaults to `LanguagePackStorage::Copy` and `LanguagePackLayer::External`, copying the data at call time. `Static` requires the bytes to stay valid and unmodified for the program lifetime. The `id` of a successful result can be passed to `removeLanguagePack()`; on failure `id` is `0`, and the existing packs and current locale stay unchanged.

## Locale selection and fallback

The initial source locale and current locale are both `zh-CN`. Locale identifiers use hyphens, for example `zh-CN`, `en-US`, `ja-JP`, `ko-KR`; input case is normalized. `en-US` is not automatically derived to `en`.

| Method | Returns | Description |
| --- | --- | --- |
| `setLocale(const char *)` | `I18nStatus` | Switches to a registered locale or the source locale and updates bindings; keeps the current locale when the requested one is unavailable |
| `setSourceLocale(const char *)` | `I18nStatus` | Sets the source locale; when the current locale equals the previous source locale, it switches along |
| `setFallbackLocales({"en-US", "ja-JP"})` | `I18nStatus` | Sets an ordered fallback list; entries without a corresponding pack are skipped; an empty list clears the configuration |
| `currentLocale()`, `sourceLocale()` | `std::string` | Returns independent strings of the current and source locale |
| `availableLocales()` | `std::vector<std::string>` | Returns registered locales and the source locale without duplicates |
| `removeLanguagePack(uint64_t)` | `I18nStatus` | Removes a pack and refreshes bindings; a nonexistent ID returns `InvalidArgument` |
| `clearLanguagePacks()` | `void` | Clears all packs and restores the source locale; bindings display source text |
| `exportMessages()` | `std::string` | Exports the registered built-in source text catalog and returns JSON |

Each message is looked up in the order current locale, explicit fallback list, source locale; within each locale, external packs override built-in packs, and within the same layer, the last registered message whose source text matches is used. When all are missing, the source text from the description is displayed. Old translations whose source text or plural source text does not match do not participate in the lookup.

After the last pack of the current locale is removed, the current locale name is kept and messages are displayed following the fallback order above. To return to the source locale, call `setLocale(sourceLocale().c_str())` explicitly or clear all language packs.

| Value | Description |
| --- | --- |
| `Success` | Operation succeeded |
| `InvalidArgument` | Invalid argument, for example an empty locale identifier or a nonexistent pack ID |
| `InvalidPack` | Language pack content failed validation |
| `UnsupportedVersion` | Language pack version not supported |
| `LocaleUnavailable` | The requested locale is not registered and is not the source locale |
| `IoError` | File or directory access failed |
| `OutOfMemory` | Memory allocation failed during language pack registration or loading |
| `Unavailable` | The current backend does not provide this operation |

## Runtime export

`exportMessages()` returns the source text catalog registered as `Builtin`, including pages already extracted but not yet opened. After the application writes the result as JSON, it can be passed directly to `sync`. It does not scan the current widget tree and does not collect unmarked plain strings.

Exported content depends on the build-time `SOURCES` and `CATALOGS`. Dynamically generated text must be added to a message catalog beforehand and embedded in the source pack. The gallery provides the [`--export-i18n`](/en/build/cpp-gallery#internationalization) command-line entry.

## C integration

The header is `<hiyui/c/i18n.h>`, also included by `<hiyui/c/hiyui.h>`. C projects use the same `target_link_i18n()` and link `hiyui-c` or the SDK's `hiyui::hiyui-c`; add `C_BINDING` explicitly when linking indirectly. Call the generated registration function before creating the interface, then call `hiyui_set_locale()`.

The following fragment binds a named argument on a created `label` handle.

```c
hiyui_text_arg_t arguments[] = {
    {.name = "name", .kind = HIYUI_TEXT_ARG_STRING, .text = "小明"}
};
hiyui_localized_text_t message = hiyui_tr("app.hello", "你好，{name}");
message.arguments = arguments;
message.argument_count = 1;
hiyui_i18n_status_t status = hiyui_label_bind_text(label, message);
```

`hiyui_tr()` and `hiyui_trn()` return descriptions referencing caller data; binding or querying copies the input at call time, after which the arguments and text can be freed. The handle must still be alive and belong to the corresponding widget type; a null handle returns `HIYUI_I18N_INVALID_ARGUMENT`. A plain text setter cancels the corresponding binding.

`hiyui_translate()`, `hiyui_current_locale()`, `hiyui_source_locale()`, `hiyui_available_locales()`, and `hiyui_i18n_export_messages()` use caller buffers. Passing `NULL, 0` queries the required byte count including the trailing NUL; a `0` return means failure. When the capacity is insufficient and greater than `0`, an empty string is written and no truncated text is returned. The locale list is newline-separated.

In `hiyui_language_pack_register()`, `static_data` and `builtin` control the data lifetime and the pack layer respectively; when both are false, the data is copied and registered as an external pack. Static C binding builds are described in [C Gallery](/en/build/c-gallery#static-linking).

## Fonts and scope

Language packs do not contain fonts. The application must provide fonts covering the target languages; embedded platforms can still use LVGL bitmap fonts.

The following command exports the set of static characters in message source text and packable translations for font subsetting.

```bash
python HIYUI/scripts/i18n.py charset messages.json locales/en-US.json --out characters.txt
```

The set does not include characters that runtime arguments may introduce; character ranges for names, user input, and similar content must be provided by the application separately. The current i18n interface provides neither RTL layout switching nor full locale-aware date, time, and number formatting.
